## Этап 2. Напоминания и дайджест · ~5 ч

Цель: бот сам пишет вовремя, а после выключенного ПК — догоняет пропущенное.

- [ ] **2.1 Тикер** — `bot/services/ticker.py`: цикл раз в `TICK_SECONDS`,
      выборка `active AND sent_at IS NULL AND fire_at <= now_utc`, отправка,
      проставление `sent_at`. Ошибка отправки не убивает цикл
      → напоминание с `fire_at` в прошлом уходит в группу в течение одного тика
- [ ] **2.2 Повторяемость** — `rrule` из `reminders.rrule` через `dateutil.rrule`,
      расчёт следующего `fire_at` после отправки
      → недельное напоминание после срабатывания получает дату следующей недели
- [ ] **2.3 Догонка** — классификация опоздания: меньше `LATE_SILENT_MIN` — просто отправить;
      до `LATE_SUMMARY_HOURS` — с пометкой «⏰ было запланировано на 19:00»;
      дольше — свернуть все пропущенные в одно сообщение «Пока меня не было: N»
      → три случая проверены на подставленном «сейчас»
- [ ] **2.4 Тесты логики** — rrule (в т.ч. `FREQ=WEEKLY;BYDAY=TU`), классификация
      опоздания на всех трёх порогах, сборка текста дайджеста из фикстуры
      → `pytest tests/` зелёный
- [ ] **2.5 `/remind <текст>`** — явное напоминание минуя разбор типа записи;
      дату тянет `dateparser` (LLM ещё нет)
      → `/remind через 2 минуты позвонить маме` создаёт `reminders` с верным `fire_at`
- [ ] **2.6 Дайджест** — `bot/services/digest.py` (события дня, задачи с дедлайном,
      просроченное, сводка покупок) + запуск из тикера по
      `families.last_digest_on < сегодня AND время наступило`
      → в 08:00 приходит один раз; повторный тик в тот же день ничего не шлёт
- [ ] **2.7 Живая панель дня** — `bot/services/panel.py`: закреплённое «📌 Сегодня»,
      `editMessageText` при изменениях, debounce 1–2 с, `asyncio.Lock` на `family_id`,
      глотание `TelegramBadRequest` «message is not modified»
      → две правки подряд дают одно отредактированное сообщение, а не два новых
- [ ] **2.8 Перевыпуск панели** — если после панели прошло больше N сообщений или больше суток,
      отправить новую и открепить старую
      → после 30 сообщений в чате панель переезжает вниз

## Сквозные напоминалки

- Всё время в БД — **в UTC**; таймзона применяется только на границе ввода и вывода
- `.env`, `data/`, `token.json`, `parse.log` — никогда в git
- Правки уже отправленных сообщений (`edited_message`) намеренно не отслеживаются
- Бот доверяет всем участникам чата — ролей и прав нет (осознанное упрощение)
- Прокси (`TELEGRAM_PROXY`, `OPENROUTER_PROXY`) заложены с этапа 0, пустые значения = напрямую
