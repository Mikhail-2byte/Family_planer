# Семейный планировщик

Telegram-бот — общая «внешняя память» семьи: задачи, заметки, покупки, события,
напоминания и утренний дайджест в одном групповом чате.

- `docs/TASKS.md` — чеклист реализации, текущий прогресс и летопись этапов
- `CLAUDE.md` — как устроен код, обоснования решений и что нельзя ломать

## Подготовка бота

1. Создать бота у [@BotFather](https://t.me/BotFather), забрать токен.
2. `/setprivacy → Disable` — иначе бот не увидит обычные сообщения в группе.
3. **Удалить бота из группы и добавить заново** — без этого смена privacy
   не подхватится.
4. `cp .env.example .env` и вписать `BOT_TOKEN`.

Команд для инициализации нет: семья создаётся сама по первому сообщению в
группе, участники — по мере того, как они пишут.

## Запуск дома (основной путь)

```bat
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
run.cmd
```

`run.cmd` накатывает миграции и поднимает бота. Docker для этого не нужен.

**Автозапуск.** Планировщик задач Windows → создать задачу.

```
Программа:      cmd.exe
Аргументы:      /c "C:\Projeck\Family_planner\run.cmd"
Рабочая папка:  C:\Projeck\Family_planner
```

**Рабочая папка обязательна:** `.env` и `data/` ищутся от текущего каталога.

**Редиректа `>> bot.log` здесь больше нет, и возвращать его не надо.** Бот пишет
`data/bot.log` сам — `RotatingFileHandler` с явной `encoding="utf-8"`, 5 МБ × 3
файла. Раньше лог собирался редиректом, и это молча его портило: при `>>`
кодировку выбирает Python по локали Windows, а не по кодовой странице консоли,
поэтому в файл ложились вперемешку cp866 (вывод `alembic`) и utf-8 — целиком его
не читал ни один декодер. Ротация появилась заодно: чистить руками больше нечего.

Вернёте редирект — сломаете **обе** вещи сразу: кодировку и ротацию. `cmd.exe`
держит файл открытым, а `RotatingFileHandler` пытается его переименовать.

Вывод самих миграций при этом не потерян: `run.cmd` уводит его в
`data/startup.log` отдельной строкой. Упавшая миграция не даёт боту стартовать,
и без её вывода причина была бы неизвестна.

**У такой задачи есть видимое окно консоли, и это опасно.** Задача с принципалом
«выполнять только для вошедшего пользователя» запускает `cmd.exe` в вашей сессии,
и его окно висит на рабочем столе. Достаточно закрыть его или нажать в нём
Ctrl+C — бот умирает, задача завершается с кодом `0xC000013A`, и `RestartOnFailure`
такое завершение не спасает. Лечится запуском через `wscript.exe`, которому
консоль не нужна вовсе:

```vbs
Set sh = CreateObject("WScript.Shell")
sh.CurrentDirectory = "C:\Projeck\Family_planer"
sh.Run "cmd /c C:\Projeck\Family_planer\run.cmd", 0, True
```

Третий аргумент `Run` — `True`, «ждать завершения». Без него `wscript` завершится
сразу, задача сочтёт себя выполненной, и защита от второго экземпляра перестанет
работать.

**Сторож вместо `RestartOnFailure`.** У задачи стоит второй триггер: ежедневный с
повтором каждые 5 минут. Пока бот работает, `MultipleInstancesPolicy = IgnoreNew`
отбрасывает эти запуски; умер — поднимется в течение пяти минут. Это надёжнее
`RestartOnFailure`, который срабатывает не на всякое завершение. Два long polling
на одном токене при этом невозможны: их отсекает тот же `IgnoreNew`.

На вкладке «Параметры» включить «Перезапускать при сбое», снять лимит времени
выполнения. На вкладке «Условия» снять «Запускать только при питании от сети» и
«Останавливать при переходе на батарею».

Триггер выбирается по тому, как поднимается прокси:

- прокси — обычное приложение из автозапуска → триггер **«При входе в систему»**
  с задержкой в минуту плюс автоматический вход в Windows (`netplwiz`);
- прокси — служба Windows → триггер **«При запуске компьютера»** и
  «Выполнять вне зависимости от регистрации пользователя».

Второй вариант надёжнее, но задача в нём работает в сессии 0, без рабочего
стола пользователя: приложения из пользовательского автозапуска там не
существует, и бот будет молча крутиться в рестартах, не найдя прокси.

Отдельно: отключить сон и гибернацию, иначе ночью бот просто не работает.

```bat
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
```

На ноутбуке этого мало — остаются сон от батареи и закрытие крышки:

```bat
powercfg /change standby-timeout-dc 0
powercfg /setacvalueindex SCHEME_CURRENT SUB_BUTTONS LIDACTION 0
powercfg /setdcvalueindex SCHEME_CURRENT SUB_BUTTONS LIDACTION 0
powercfg /setactive SCHEME_CURRENT
```

**Тихий режим.** Домашний ПК остаётся рабочим местом, и круглосуточная работа
ради бота на 22 МБ тянет за собой Chrome, игровые лаунчеры и прочее. Настройка
машины под это лежит **вне репозитория** — в `C:\Projeck\_quiet\`: сторож
`quiet-mode.ps1` (задача Планировщика `QuietMode`) через час без клавиатуры и
мыши закрывает тяжёлые приложения из `apps.txt` и гасит SQL Server; `quiet-now.cmd`
делает то же немедленно. Бот, прокси и редактор — в зашитом списке
неприкасаемых.

Здесь только указатель: это настройка конкретной машины, а не часть проекта, и
в git ей делать нечего. При переезде её придётся собрать заново — как и задачу
Планировщика, и прокси.

**Ночной сон.** Круглосуточная работа не обязательна, и это не компромисс, а
осознанный выбор: во сне бот молчит, но почти ничего не теряет. S3 обесточивает
процессор и сетевую карту, процесс замирает — но **не перезапускается**, поэтому
`drop_pending_updates` не срабатывает, и Telegram отдаёт накопленные сообщения
после пробуждения (он держит их до 24 часов). Напоминания догоняет тикер из базы
по обычным правилам опоздания, утреннюю сводку — `digest.is_due` по
`last_digest_on`. Разница с перезапуском именно здесь: рестарт пропущенные
сообщения выбрасывает, сон — нет.

На этой машине сон настроен задачами `SleepAtNight` (с 01:00 каждые 15 минут до
05:00) и `WakeMorning` (07:45, с флагом «разбудить компьютер»). Резко машина не
выключается: между «пора спать» и сном стоят четыре заслона — флаг
`no-sleep.flag` (ставится `stay-awake.cmd` на одну ночь), 25 минут без
клавиатуры и мыши, проверка `powercfg /requests` на воспроизведение звука или
видео и окно с двухминутным обратным отсчётом, которое отменяется движением
мыши. Повтор каждые 15 минут нужен именно поэтому: отложенный сон случится,
когда человек уйдёт, а не будет пропущен до завтра. Подъём на 15 минут раньше
сводки намеренно: к 08:00 бот должен уже опрашивать Telegram, а не поднимать сеть
и прокси. Таймеры пробуждения должны быть разрешены в схеме питания
(`SUB_SLEEP RTCWAKE = 1`), а в вызове `SetSuspendState` третий аргумент —
`disableWakeEvent` — обязан быть `false`, иначе машина проспит до тычка в
клавиатуру.

**И третья настройка, из-за которой всё это выглядит сломанным, хотя работает.**
Кроме обычного таймаута сна есть скрытый — «сон после автоматического
пробуждения» (`SUB_SLEEP 7bc4a2f9-d8fc-4469-b07b-33eb785aaca0`), по умолчанию
**120 секунд**. Машина исправно просыпается по таймеру, а через две минуты без
клавиатуры и мыши уходит обратно в сон — и к 08:00 её снова нет. Обычный
`standby-timeout-ac 0` на него не влияет вовсе, и `powercfg /query` его не
показывает, пока не снимешь скрытость:

```bat
powercfg -attributes SUB_SLEEP 7bc4a2f9-d8fc-4469-b07b-33eb785aaca0 -ATTRIB_HIDE
powercfg /setacvalueindex SCHEME_CURRENT SUB_SLEEP 7bc4a2f9-d8fc-4469-b07b-33eb785aaca0 0
powercfg /setactive SCHEME_CURRENT
```

Симптом в журналах узнаётся так: в системном журнале событие 42 «entering
sleep» с причиной **System Idle** через ~2 минуты после пробуждения, а в логе
бота — переподключение и следом тишина до того момента, когда к машине подошёл
человек.

Чего в этой схеме не бывает: чтобы бот **работал во сне**. «S0 Low Power Idle»,
где фон живёт во сне, поддерживается не всяким железом — проверяется командой
`powercfg /a`. Либо машина работает, либо бот не работает.

## Переезд на другой ПК

Переносить надо три вещи: код, `.env` и базу. Код едет через git, остальное — в
`.gitignore` и копируется руками. Плюс четвёртое, чего в репозитории нет вовсе,
— задача Планировщика и прокси.

**На старой машине.** Закоммитить и запушить всё, иначе `git clone` на новой
даст код на этап назад. Слепок версий `pip freeze` — страховка: в
`requirements.txt` только диапазоны, лок-файла нет.

**На новой машине, пока старый бот ещё работает.** Python той же минорной
версии, прокси (проверить `curl.exe -x <прокси> https://api.telegram.org/`),
`git clone`, `python -m venv .venv`, установка зависимостей. Положить `.env` и
поправить в нём `TELEGRAM_PROXY`. **`.env` кладётся до миграций:**
`alembic/env.py` импортирует `bot.config`, и без `BOT_TOKEN` падает
`ValidationError`, не дойдя до базы. Прогнать `pytest`. Бота **не запускать**:
два long polling на одном токене дерутся за `getUpdates`.

**Перенос базы — здесь начинается простой.** Остановить бота на старой машине,
убедиться, что процессов `-m bot` не осталось, и скопировать **три** файла:
`data\family.db`, `data\family.db-wal`, `data\family.db-shm`. Именно три:
включён WAL, и в `-wal` лежат самые свежие записи — копия одного `family.db`
их потеряет. По желанию — `data\backups\` и `data\parse.log`, для работы они
не нужны.

Запасной путь, если копировать между машинами неудобно: **до** остановки нажать
`/backup` в чате — придёт самодостаточный снимок, `-wal` к нему не нужен. Цена:
база семьи навсегда осядет в облаке Telegram, а ежедневный бэкап держат на
диске именно чтобы этого не случилось.

**Первый запуск.** `alembic upgrade head` (на перенесённой базе no-op, но
проверяет, что `.env` читается), затем `run.cmd` глазами в консоль — должны
появиться «Запуск @…», «Тикер запущен» и «Run polling». Тишина после «Запуск»
без единой ошибки означает, что прокси не пропускает. В группе проверить
`/today` и `/family`: они покажут перенесённые данные, а не пустоту. Панель
«📌 Сегодня» бот продолжит **редактировать**, а не выпустит заново —
`panel_message_id` приехал вместе с базой.

**Погасить старую машину как источник.** Задачу Планировщика там удалить, а не
отключить: включённая по случайности, она даст второй экземпляр на том же
токене. `data\` не стирать пару недель — это единственная страховка.

**Что теряется, и это штатно:** незавершённые `/new`, неподтверждённые карточки
разбора, ожидания правки реплаем и приглашения «🎤 Голосом» — всё это живёт в
памяти процесса; плюс сообщения, пришедшие в чат за время простоя
(`drop_pending_updates=True` на старте). Напоминания не теряются — их догоняет
тикер из базы, но форма зависит от длины простоя: до `LATE_SILENT_MIN` минут
незаметно, до `LATE_SUMMARY_HOURS` часов с пометкой об опоздании, дольше —
одной сводкой.

## Переезд на VPS

Для сервера в репозитории лежат `Dockerfile` и `docker-compose.yml` — там
контейнер оправдан: одинаковое окружение и автоперезапуск. Системных
зависимостей у образа нет: `ffmpeg`, который закладывался под этап 5, не
понадобился — расшифровка принимает `ogg/opus` Telegram как есть.

```bash
# скопировать на сервер data/ и .env
chown -R 1000:1000 ./data   # процесс в контейнере не root и иначе не создаст БД
docker compose up -d
docker compose logs -f
```

## Стоимость LLM

Разбор свободного текста идёт по цепочке бесплатных моделей: первым —
Groq (`openai/gpt-oss-120b`), запасными — OpenRouter (`minimax/minimax-m3:free`
и `dots-studio/dots-3-note-preview:free`). Все бесплатны, поэтому фактическая
цена — **0 ₽/мес**. Цифра из наблюдения, а не из прайса: платить не за что.

Groq стоит первым по замеру 01.09.2026 на реальном промпте бота: 1.4 с против
2.0–3.1 с у OpenRouter, 5 из 5 верного JSON и правильный `FREQ=MONTHLY;BYDAY=2TU`
на «каждый второй вторник месяца». Плюс 1000 запросов в сутки вместо 50.

Настоящая цена бесплатного тира — не деньги, а лимиты:

| Вендор | Запросов в сутки | Прочее |
|---|---|---|
| Groq (первое звено) | 1000 | 8000 токенов в минуту — при промпте ~1200 токенов это около пяти фраз подряд |
| OpenRouter, без пополнения | 50 | 20 запросов в минуту |
| OpenRouter, после разовой покупки кредитов на $10 | 1000 | там же |

У OpenRouter лимит считается **глобально на аккаунт**, новые ключи его не
обходят (`https://openrouter.ai/docs/api-reference/limits`). У Groq — **по
модели**: расшифровка голоса (`whisper-large-v3-turbo`) тратит свой счётчик, а
не общий с разбором, и это проверено по заголовкам `x-ratelimit-*`.

Бот отзывается только на явное обращение — команду, ответ на своё сообщение,
упоминание или фразу с `+`, — поэтому в сутки уходят единицы запросов и до
лимита далеко.

**Замер 28.08.2026: 10 вызовов за сутки** (7 текстовых разборов и 3 голосовых)
— это 20 % суточного лимита. Причём день был не обычный, а день живых прогонов:
семья в этот день не столько пользовалась ботом, сколько проверяла его. Обычный
день будет меньше, но на одном замере это утверждать нельзя — цифра тут одна и
взята с потолка ровно настолько, насколько один день репрезентативен. Режим «слушать
всё» отменён именно из-за этой таблицы: вызов на каждое сообщение чата выбрал бы
суточный лимит, после чего перестал бы работать и префикс `+`.

**Запасные модели.** У бесплатной модели провайдер обычно ровно один, и когда
он моргает, разбор молча уезжает на `dateparser`. 01.09.2026 так и вышло:
GMICloud — единственный провайдер `minimax/minimax-m3:free` — ответил 401, и
разбора не стало. Поэтому цепочка задаётся в `LLM_MODELS` записями вида
`вендор:модель`, и смысл списка не в качестве, а в **независимости отказов**.
Запасная у того же провайдера бесполезна; разные вендоры надёжнее разных
провайдеров внутри одного OpenRouter, у которого общий фронт, общий биллинг и
общая страница статуса. Кто обслуживает модель OpenRouter, видно по
`https://openrouter.ai/api/v1/models/<id>/endpoints`.

Две мины при подборе звена, обе стоили времени: Groq отвергает поле приватности
OpenRouter (`400 property 'provider' is unsupported`), а модель, чей провайдер
учится на бесплатных запросах, отвечает OpenRouter'у `404 No endpoints found
matching your data policy` — то есть выглядит несуществующей, хотя дело в нашем
`data_collection=deny`.

Жив ли ИИ прямо сейчас — отвечает команда **`/ai`**: она делает настоящий
запрос той же цепочкой и показывает ответившую модель, время, расход за сутки и
когда ИИ отказывал в последний раз.

**Пересчёт по логу** — понадобится при переходе на платную модель. Бот пишет
`data/parse.log` JSON-строками; считать надо **поле `calls`, а не строки**: одна
фраза с цепочкой и повторами стоит нескольких запросов, а неудачные тратят квоту
наравне с удачными. Пробы `/ai` идут строкой `event=probe` и тоже считаются.

```bash
python -c "import json,collections;from pathlib import Path;c=collections.Counter();[c.update({json.loads(l)['at'][:10]: json.loads(l).get('calls', 1 if json.loads(l).get('via')=='llm' else 0)}) for l in Path('data/parse.log').read_text(encoding='utf-8').splitlines() if json.loads(l).get('event') in ('parse','probe')];[print(d, n) for d, n in sorted(c.items())]"
```

Печатает «дата · сколько запросов ушло». Умножить на цену модели за вызов — это
и есть месячная смета.

## Стоимость расшифровки голоса

Второй внешний сервис и **вторая, независимая квота**: голосовые уходят в Groq
(`whisper-large-v3-turbo`), а не в OpenRouter. Это сделано намеренно — иначе
голос выедал бы те же 50 запросов в сутки, на которых держится текстовый `+`.

| Что | Бесплатный тир Groq |
|---|---|
| Запросов в минуту | 20 |
| Запросов в сутки | 2000 |
| Секунд аудио в сутки | 28 800 (8 часов) |
| Карта при регистрации | не нужна |

Сверх тира — $0.04 за час аудио. Для семейного чата это тоже **0 ₽/мес**.

Ключ берётся на `console.groq.com` и кладётся в `.env` как `STT_KEY`. Пока он
пуст, кнопка «🎤 Голосом» честно отвечает, что расшифровка выключена, а
остальной бот работает как раньше. Голосовые считаются отдельной строкой
`event=voice` в том же `data/parse.log`.

## Разработка

```bash
.venv\Scripts\pip install -r requirements-dev.txt

ruff check .    # линтер
mypy            # проверка типов
pytest          # тесты
```

Все три обязаны быть зелёными — их же гоняет CI на каждый push и PR
(`.github/workflows/ci.yml`). Запускать **из корня проекта**: `bot/config.py`
создаёт `Settings()` на импорте, и из другого каталога падает даже `pytest`.

`ruff format` в проекте нет намеренно: он переформатировал бы 45 файлов из 72,
